## (3) Detailed reviews

1. **Architect Modern Web Applications with ASP\.NET Core and Azure** — _Steve "ardalis" Smith_ — **2024**
    - **Links**: [Local](architecting-modern-web-apps-azure/Architecting-Modern-Web-Applications-with-ASP.NET-Core-and-Azure.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/architecture/modern-web-apps-azure/)
    - **Extended Summary**: A guide to architecting modern, deployable ASP\.NET Core web applications with Azure. It advocates a modular-monolith approach where that choice best fits the business and operational constraints.
    - **Review**: A clear, pragmatic counterweight to microservice-first thinking. It explains architectural trade-offs well, though it is less useful for distributed-system design.
    - **Recommended Use**: Read before designing or modernizing a modular monolith.

2. **Blazor for ASP\.NET Web Forms Developers** — _Jeffrey T. Fritz_ — **2024**
    - **Links**: [Local](blazor-for-web-forms-developers/Blazor-for-ASP-NET-Web-Forms-Developers.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/architecture/blazor-for-web-forms-developers/)
    - **Extended Summary**: Translates Web Forms concepts, development practices, and migration concerns into Blazor's component-based model. It includes strategies for incrementally moving existing applications.
    - **Review**: An approachable bridge for teams with Web Forms experience. The direct comparisons make the transition concrete, but it assumes familiarity with legacy ASP\.NET patterns.
    - **Recommended Use**: Read when planning an incremental Web Forms-to-Blazor migration.

3. **Enterprise Application Patterns Using .NET MAUI** — _David Britch_ — **2024**
    - **Links**: [Local](maui/Enterprise-Application-Patterns-Using-.NET-MAUI.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/architecture/maui/)
    - **Extended Summary**: Applies established enterprise mobile patterns to .NET MAUI applications, including separation of concerns, navigation, dependency injection, and testability.
    - **Review**: A compact and relevant architectural guide for MAUI teams. It is pattern-driven rather than a comprehensive MAUI API reference.
    - **Recommended Use**: Use to shape a maintainable MAUI application before implementation.

4. **Architecting Cloud-Native .NET Apps for Azure** — _Rob Vettor and Steve "ardalis" Smith_ — **2023**
    - **Links**: [Local](cloud-native/Architecting-Cloud-Native-NET-Apps-for-Azure.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/architecture/cloud-native/)
    - **Extended Summary**: Connects cloud-native principles to Azure implementation choices for resilient, observable, distributed applications. It covers containers, orchestration, backing services, and automated operations.
    - **Review**: Broad and well structured, connecting cloud-native concepts to practical Azure choices. Some platform guidance will need updating as Azure services evolve.
    - **Recommended Use**: Use to establish cloud-native architectural principles for a new system.

5. **Containerized Docker Application Lifecycle with Microsoft Platform and Tools** — _Cesar de la Torre_ — **2023**
    - **Links**: [Local](containerized-lifecycle/Containerized-Docker-Application-Lifecycle-with-Microsoft-Platform-and-Tools.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/architecture/microservices/)
    - **Extended Summary**: Describes an end-to-end lifecycle for building, testing, deploying, and operating Dockerized applications with Microsoft tooling and Azure services.
    - **Review**: A practical lifecycle view that connects developer tools to delivery concerns. It is most valuable for Microsoft-centric teams rather than as a neutral Docker reference.
    - **Recommended Use**: Read when standardizing a container development and delivery workflow.

6. **Dapr for .NET Developers** — _Microsoft .NET team_ — **2023**
    - **Links**: [Local](dapr-for-net-developers/Dapr-for-NET-Developers.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/architecture/dapr-for-net-developers/)
    - **Extended Summary**: Introduces Dapr's distributed-application building blocks and shows how .NET services can use them for communication, state, events, bindings, and actors.
    - **Review**: One of the more hands-on guides in the collection, with a coherent explanation of Dapr abstractions. It requires supplementary operational guidance for production adoption.
    - **Recommended Use**: Use when evaluating or implementing Dapr in a distributed application.

7. **DevOps for ASP\.NET Core Developers** — _Microsoft .NET team_ — **2023**
    - **Links**: [Local](devops-aspnet-core/DevOps-for-ASP.NET-Core-Developers.pdf) · [Web](https://learn.microsoft.com/en-us/devops/develop/)
    - **Extended Summary**: Provides an ASP\.NET Core-oriented introduction to automated build, test, release, infrastructure, and monitoring practices.
    - **Review**: A focused, accessible starting point for development teams adopting DevOps. It favors breadth over detailed pipeline implementation.
    - **Recommended Use**: Read before establishing a delivery baseline for an ASP\.NET Core application.

8. **gRPC for WCF Developers** — _Microsoft .NET team_ — **2023**
    - **Links**: [Local](grpc-for-wcf-developers/gRPC-for-WCF-Developers.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/architecture/grpc-for-wcf-developers/)
    - **Extended Summary**: Helps WCF developers map service contracts, communication styles, and implementation techniques to gRPC and Protocol Buffers.
    - **Review**: A strong migration-focused guide with useful conceptual mapping between WCF and gRPC. It is deliberately specialized and does not replace broader API design material.
    - **Recommended Use**: Read when replacing WCF services with gRPC endpoints.

9. **.NET Microservices: Architecture for Containerized .NET Applications** — _Cesar de la Torre, Bill Wagner, and Mike Rousos_ — **2023**
    - **Links**: [Local](microservices/NET-Microservices-Architecture-for-Containerized-NET-Applications.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/architecture/microservices/)
    - **Extended Summary**: An end-to-end architecture reference for containerized .NET microservices, spanning design, data, communication, resilience, and deployment concerns.
    - **Review**: The collection's most comprehensive architecture reference, combining rationale, patterns, and implementation detail. Its breadth makes it better for study and reference than a quick introduction.
    - **Recommended Use**: Use as the primary reference when designing or evolving .NET microservices.

10. **Modernize Desktop Apps on Windows with .NET** — _Microsoft .NET team_ — **2023**
    - **Links**: [Local](modernize-desktop-apps/Modernize-Desktop-Apps-on-Windows-with-NET.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/desktop/)
    - **Extended Summary**: Explains modernization choices for WinForms and WPF applications, including upgrading to modern .NET and using newer Windows application capabilities.
    - **Review**: A useful decision guide that frames modernization paths clearly. It is less detailed on complex legacy dependencies and rollout strategy.
    - **Recommended Use**: Read when assessing a WinForms or WPF modernization initiative.

11. **Modernize Existing .NET Applications with Azure Cloud and Windows Containers** — _Microsoft .NET team_ — **2023**
    - **Links**: [Local](modernize-with-azure-containers/Modernize-Existing-.NET-applications-with-Azure-cloud-and-Windows-Containers.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/architecture/modernize-with-azure-containers/)
    - **Extended Summary**: Introduces an Azure and Windows-container path for moving established .NET applications toward cloud operations without a wholesale rewrite.
    - **Review**: A compact, scenario-oriented introduction to container-based modernization. Best used alongside current Azure and container-platform documentation.
    - **Recommended Use**: Use to evaluate a containerization path for legacy Windows workloads.

12. **Porting Existing ASP\.NET Apps to .NET** — _Steve "ardalis" Smith_ — **2023**
    - **Links**: [Local](porting-existing-aspnet-apps/Porting-Existing-ASP.NET-Apps-to-.NET.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/core/porting/)
    - **Extended Summary**: Covers assessing existing ASP\.NET applications, resolving dependencies, and taking an incremental approach to porting them to modern .NET.
    - **Review**: A pragmatic migration playbook that highlights the important assessment work. It is strongest for conventional applications and less prescriptive for highly customized legacy stacks.
    - **Recommended Use**: Read before estimating an ASP\.NET Framework-to-.NET migration.

13. **Serverless Apps: Architecture Patterns and Azure Implementation** — _Microsoft .NET team_ — **2023**
    - **Links**: [Local](serverless/Serverless-apps-Architecture-patterns-and-Azure-implementation.pdf) · [Web](https://learn.microsoft.com/en-us/azure/azure-functions/functions-overview)
    - **Extended Summary**: Introduces serverless design patterns and Azure services for event-driven workloads, workflows, and automatically scaling compute.
    - **Review**: A short, useful architectural primer that explains where serverless fits. It does not go deeply into governance, testing, or complex production operations.
    - **Recommended Use**: Use to decide whether a workload is a good serverless candidate.

14. **Performance Improvements in .NET 7** — _Stephen Toub_ — **2022**
    - **Links**: [Local](blogs/net7perf/Performance-Improvements-in-NET7.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-7)
    - **Extended Summary**: Collects runtime, library, and tooling performance improvements introduced in .NET 7, with implementation detail and benchmarks.
    - **Review**: A deep, evidence-led technical reference with many focused examples. It is excellent for understanding platform changes, but not a general performance-tuning tutorial.
    - **Recommended Use**: Consult when profiling .NET 7 workloads or learning runtime internals.

15. **Azure Quick Start for .NET Developers** — _Cesar de la Torre, Michael Crump, Barry Luijbregts, and Beth Massi_ — **2019**
    - **Links**: [Local](azure-quick-start/Azure-Quick-Start-for-NET-Developers.pdf) · [Web](https://learn.microsoft.com/en-us/azure/developer/dotnet/)
    - **Extended Summary**: Introduces major Azure services and the development workflow for deploying, hosting, and storing data in .NET applications.
    - **Review**: A concise orientation that is easy to scan. Its service details reflect an older Azure landscape, so pair it with current Azure documentation.
    - **Recommended Use**: Use as a quick cloud vocabulary and service overview.

16. **.NET for Java Developers** — _Alessandro Del Sole_ — **2018**
    - **Links**: [Local](dotnet-for-java-developers/dotnet-for-java-developers-ebook.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/core/porting/)
    - **Extended Summary**: Compares .NET platform concepts, tools, and development practices to the Java ecosystem to accelerate onboarding.
    - **Review**: A concise translation guide that lowers the initial learning curve. Its high-level platform comparisons remain useful, but version-specific tooling is dated.
    - **Recommended Use**: Use as an onboarding primer for Java developers joining a .NET team.

17. **Enterprise Application Patterns using Xamarin.Forms** — _David Britch_ — **2017**
    - **Links**: [Local](xamarin-forms/Enterprise-Application-Patterns-using-XamarinForms.pdf) · [Web](https://learn.microsoft.com/en-us/dotnet/architecture/maui/)
    - **Extended Summary**: Presents enterprise mobile architecture patterns for Xamarin.Forms, with emphasis on MVVM, navigation, dependency injection, and testing.
    - **Review**: A solid historical reference for Xamarin.Forms architecture, but Xamarin.Forms is retired and the material should be applied through its .NET MAUI successor.
    - **Recommended Use**: Use for legacy Xamarin.Forms maintenance or as background before migrating to MAUI.
